\section{Introduction}
% 第一段：PDP/data integrity的重要性
% 第二段：多项式承诺广泛应用在data integrity中
% 第三段：用户的文件多，逐个验证代价大
% 第四段：由于文件大，data integrity通常通过抽样检查
% 第五段：抽样过程中如果抽样点、掩码不合理，会导致隐私泄露
% 第六段：为解决上述问题，我们提出FoldAudit
The exponential growth of global data generation has driven a paradigm shift toward decentralized and cloud-based storage architectures. By outsourcing data to remote storage providers, individuals and organizations significantly reduce local hardware maintenance costs while benefiting from elastic scalability, geographic redundancy, and high availability. However, this outsourcing model inherently relinquishes physical control over the stored assets, exposing them to multifaceted risks such as hardware degradation, silent data corruption, and economically motivated data deletion or compression by untrusted storage providers. To mitigate these threats and restore trust in distributed storage ecosystems, Provable Data Possession (PDP) and Proof of Retrievability (PoR) schemes have emerged as foundational cryptographic primitives. These protocols enable data owners or delegated auditors to efficiently verify the integrity of outsourced data without retrieving the entire dataset, thereby ensuring continuous data availability, regulatory compliance, and accountability in modern storage networks.

Recent advancements in cryptographic primitives have significantly optimized the efficiency and scalability of data integrity auditing. Among these, Polynomial Commitment Schemes (PCS), particularly the Kate-Zaverucha-Goldberg (KZG) construction, have been widely adopted in state-of-the-art PDP designs. By encoding data blocks as coefficients of low-degree polynomials over a finite field, PCS enables compact, constant-size commitments and supports homomorphic aggregation of multiple block tags. This algebraic structure allows cloud servers to generate succinct proofs of possession through polynomial evaluation and quotient computation, while verifiers can validate correctness using a minimal number of bilinear pairings. Consequently, polynomial commitments have become the cornerstone of lightweight, publicly verifiable auditing frameworks, drastically reducing communication bandwidth and on-chain storage overhead compared to traditional hash-based or signature-based approaches. Their compatibility with structured reference strings (SRS) and efficient synthetic division algorithms further positions them as ideal candidates for large-scale storage verification.

Despite these cryptographic improvements, practical storage deployments frequently involve massive-scale data repositories comprising thousands of files distributed across multiple storage nodes, providers, or geographic regions. Conventional PDP protocols process each file independently, requiring separate proof generation, transmission, and verification rounds for every audited dataset. This linear scaling introduces severe computational and economic bottlenecks, particularly in blockchain-assisted auditing systems where smart contract execution costs (gas) and on-chain proof storage scale directly with the number of files. As audit frequencies increase and batch sizes grow, the cumulative overhead of independent verifications rapidly degrades system throughput, inflates operational expenses, and strains verifier resources. Therefore, developing a secure and efficient multi-file batch verification mechanism that compresses multiple integrity checks into a single, constant-size cryptographic operation has become a critical research imperative for scalable decentralized storage.

Given the substantial size of individual files in real-world applications, auditing every data block is computationally prohibitive and economically unviable. To address this challenge, modern PDP schemes universally employ probabilistic sampling strategies. During an audit round, the verifier randomly selects a subset of data blocks and assigns independent random coefficients to construct a linear combination of challenged sectors. This approach reduces the proof size and verification complexity from linear $O(n)$ to constant or logarithmic $O(c)$ with respect to the total number of blocks, where $c \ll n$ denotes the challenge size. By carefully calibrating the number of sampled blocks, auditors can achieve arbitrarily high detection probabilities for data corruption while maintaining minimal communication and computation overhead. The randomness of the challenge set ensures that malicious providers cannot precompute proofs or selectively store only frequently accessed blocks without facing a high risk of detection.

However, the introduction of probabilistic sampling and homomorphic aggregation introduces subtle yet critical privacy vulnerabilities. In many existing batch auditing designs, challenge generation mechanisms, evaluation points, and masking techniques are either oversimplified or structurally coupled across files. If challenge points are shared, folding weights are predictable, or masking scalars lack cryptographic commitment, an honest-but-curious verifier or public ledger observer can exploit the linear algebraic structure of aggregated evaluations. Through cross-round correlation analysis or linear system inversion on publicly disclosed challenge-response transcripts, adversaries may reconstruct underlying polynomial evaluations $f(r_i)$ or even infer sensitive sector values. Such privacy leakage fundamentally contradicts the confidentiality requirements of modern cloud and decentralized storage, highlighting the necessity of integrating rigorous, one-time pad masking with binding commitments directly into the batch verification algebraic structure to prevent statistical inference attacks.

To address the aforementioned challenges, we propose \textbf{FoldAudit}, a novel batch-verifiable PDP scheme that simultaneously achieves constant-time multi-file verification, tight cryptographic soundness, and robust evaluation privacy. FoldAudit introduces a layered algebraic folding architecture: (i) independent per-file challenge points $\{r_i\}$ to structurally isolate file-specific quotient polynomials and prevent cross-file pole cancellation; (ii) a Fiat-Shamir derived random folding scalar $\rho$ applied to quotient commitments after they are fixed, ensuring that batch aggregation remains algebraically unpredictable and bias-resistant; and (iii) fresh one-time pad masking coupled with group commitments to statistically hide challenged evaluations and point evaluations from curious verifiers. By leveraging the Zero Multiplicity Distance Lemma, we formally derive a tight soundness error bound $\epsilon \leq \frac{s+m-1}{p-m}$, guaranteeing that any adversarial error cancellation or adaptive forgery is detected with overwhelming probability. Theoretical analysis and experimental evaluations demonstrate that FoldAudit reduces on-chain verification to a constant number of pairings independent of batch size, supports stateless dynamic file updates without global state recomputation, and maintains provable privacy against honest-but-curious auditors, making it highly suitable for large-scale, privacy-sensitive decentralized storage environments.

\subsection{KZG Polynomial Commitment}
We employ a KZG-type polynomial commitment scheme over a bilinear group tuple $(\GG_1, \GG_2, \GG_T, e)$ of prime order $p$. Here, $e: \GG_1 \times \GG_2 \to \GG_T$ is an efficiently computable, non-degenerate bilinear map. Let $g \in \GG_1$ and $h \in \GG_2$ be publicly known generators. 

A trusted setup generates a secret trapdoor $\tau \in \FF_p$ and publishes a structured reference string (SRS) supporting polynomials up to degree $s-1$:
$$
\SRS = \left( g, g^{\tau}, g^{\tau^2}, \dots, g^{\tau^{s-1}}, h, h^{\tau} \right).$$
For a polynomial $f(X) = \sum_{k=0}^{s-1} a_k X^k \in \FF_p^{<s}[X]$, its commitment is computed in the exponent as
\begin{equation}\label{eq:kzg_commitment}
    C_f := g^{f(\tau)} = \prod_{k=0}^{s-1} \left(g^{\tau^k}\right)^{a_k} \in \GG_1
    % \footnote{Although the server in our application does not know \(\tau\), it can still evaluate \(C_f\) using the public parameters and polynomial coefficients. Most importantly, \(C_f\) coincides with the file chunk tag, making it the foundation of our provable data possession scheme.}
\end{equation}

To prove an evaluation $f(z) = v$, the prover computes the quotient commitment $\pi := g^{w(\tau)}$ where $w(X) = (f(X) - v)/(X - z)$. The verifier checks the pairing equation
\begin{equation}
e\left(C_f \cdot g^{-v},\, h\right) \stackrel{?}{=} e\left(\pi,\, h^{\tau - z}\right),
\end{equation}
which holds if and only if $f(\tau) - v = (\tau - z)w(\tau)$ and $w(X)$ is the quotient polynomial. Under the $q$-SDH assumption~\cite{}, the scheme is evaluation-binding and knowledge-sound.


\subsection{Multi-Polynomial Batch Evaluation (MPBE)}
\label{sec:multi_poly_batch_evaluation}
We present the algebraic foundation and the resulting interactive protocol for verifying multiple polynomial evaluations simultaneously.

\begin{lemma}[Zero Multiplicity Distance Lemma]\label{lem:zmdl}
Consider pairs of polynomials $(f_1, v_1), \dots, (f_m, v_m) \in \FF_p[X]$, where the root sets $\text{zeros}(v_i) := \{z \in \FF_p \mid v_i(z)=0\}$ are pairwise disjoint. Define the rational function: 
$$w(X) := \sum_{i=1}^m \frac{f_i(X)}{v_i(X)},$$ and let $k_1 := \max_i (\deg(f_i) - \deg(v_i))$ and $k_2 := \sum_i \deg(v_i)$. The \emph{Zero Multiplicity Distance Lemma} states that if the relative Hamming distance between $w$ and the space of degree-$\le k_1$ polynomials satisfies
\[
\Delta\bigl(w, {\FF_p}_{\le k_1}[X]\bigr) \le 1 - \frac{k_1+k_2+1}{|\FF_p| - |Z|},
\]
where $Z := \bigcup_i \text{zeros}(v_i)$, then for every $i$, the zero multiplicities of $v_i$ are contained in those of $f_i$ (denoted $\text{zmult}(v_i) \sqsubseteq \text{zmult}(f_i)$). Intuitively, this means each denominator $v_i(X)$ must exactly divide its numerator $f_i(X)$ at all roots (counting multiplicity). If any division fails, $w(X)$ develops poles or non-polynomial behavior near the roots of $v_i$, forcing it to deviate significantly from any low-degree polynomial. Consequently, a single random evaluation of $w$ will detect such algebraic inconsistencies with high probability.
\end{lemma}



\noindent\textbf{Application to Multi-Polynomial Batch Evaluation.}
Lemma~\ref{lem:zmdl} provides a versatile algebraic backbone that naturally supports a two-level folding structure. Let $\rho_2 \in \FF_p$ compress multiple polynomials evaluated at the same point, and let $\rho_1 \in \FF_p$ fold quotient checks across distinct evaluation points. The general batch quotient-sum polynomial can be expressed as:
\[
W(X) := \sum_{x \in S} \rho_1^{\text{idx}(x)-1} \left( \sum_{i=1}^{\ell_x} \rho_2^{i-1} \cdot \frac{p_{x,i}(X) - y_{x,i}}{X - x} \right),
\]
where $\text{idx}(x)$ maps each point $x$ to a unique batch index. This structure simultaneously handles intra-point polynomial compression (via $\rho_2$) and inter-point batch aggregation (via $\rho_1$).

In our Batch-PDP scenario, however, each challenge point $r_i$ corresponds to exactly one aggregated file polynomial $f_i(X)$ (i.e., $\ell_{r_i} = 1$ for all $i \in [m]$). Consequently, the inner summation trivially collapses to a single term, rendering $\rho_2$ redundant. We retain only the cross-file folding scalar $\rho \coloneqq \rho_1$, which is cryptographically essential for preventing adversarial error cancellation across distinct files. The polynomial simplifies to:
\[
W(X) := \sum_{i=1}^{m} \rho^{i-1} \cdot \frac{f_i(X) - y_i}{X - r_i}.
\]
The verifier samples $z \in \FF_p \setminus \{r_i\}_{i=1}^m$ and accepts iff the evaluated sum matches the prover's committed opening $V_W=W(z)$. The consistency check directly instantiates Equation: $V_W \stackrel{?}{=} \sum_{i=1}^m \rho^{i-1} \frac{f_i(z) - y_i}{z - r_i}.$
% We can infer that $k_2 =\sum_i \deg(v_i)=m$.
By Lemma~\ref{lem:zmdl} if any claim $f_i(r_i) = y_i$ is false, $W(X)$ develops a pole at $r_i$ and deviates significantly from any degree-$(k_1-2)$ polynomial.

\subsection{Merkle Tree}
A Merkle tree is a binary hash-based commitment structure that provides authenticated membership proofs for a set of values. Let $H_1: \{0,1\}^* \to \FF_p$ be a collision-resistant cryptographic hash function. For a sequence of $n$ data items $\{d_j\}_{j=1}^n$, the leaves are constructed as indexed hashes: $L_j := H_1(j \,\|\, d_j), j \in [n].$
Internal nodes are recursively computed as $N_{k} = H_1(N_{2k} \,\|\, N_{2k+1})$ until a single root hash $\Gamma$ is obtained. The root $\Gamma$ uniquely commits to the entire dataset under the collision resistance of $H_1$.
To prove that a value $d_j$ belongs to the committed set, the prover provides an \textit{authentication path} consisting of the sibling hashes along the route from leaf $L_j$ to the root. The verifier recomputes the root from the path and checks equality with the trusted root $\Gamma$.
Apparently, each authentication path requires $\log n$ filed $\FF_p$ elements.

\subsection{System Model}
\paragraph{System Entities}
We consider a batch-verifiable Provable Data Possession (PDP) architecture comprising three entities: Data Owner, a Cloud Server and Verifier.
\begin{itemize}
    \item \textbf{Data Owner} (DO): The DO outsources a batch of $m$ files to the CS for long-term storage. To ensure data integrity without maintaining local copies, the DO delegates periodic auditing to the V.
    \item \textbf{Cloud Server} (CS): The CS is modeled as untrusted and computationally bounded: it may delete, corrupt, or selectively withhold files or chunks to save storage or bandwidth. 
    \item \textbf{Verifier} (V): The V is honest-but-curious. It executes the auditing protocol faithfully but may attempt to infer sensitive information from audit transcripts.
\end{itemize}

\paragraph{File Representation}
A file is divided into multiple chunks, and each \textbf{chunk} can be represented through polynomial coefficients. Each coefficient is referred to as a \textbf{sector}.
Let $m$ denote the number of files in a single audit batch, $n$ the number of chunks per file, $s$ the number of sectors per chunk. Namely, each chunk is parsed into $s$ field elements from $\FF_p$ and algebraically encoded as a polynomial of degree at most $s-1$:
$$
    f_{i,j}(X) = \sum_{k=0}^{s-1} m_{i,j,k} X^k, \quad i \in [m], \; j \in [n],
$$
where $m_{i,j,k}$ represents the $k$-th sector of the $j$-th chunk in file $i$. 
A \textbf{tag} is used to represent the \(j\)-th chunk through a KZG polynomial commitment. i.e., $\sigma_{i,j} =  g^{f_{i,j}(\tau)} \in \GG_1$ by Equation~\eqref{eq:kzg_commitment}. Further, tags of each file are organized into a Merkle Tree to guarantee correct indexing and membership.

\paragraph{Protocol Workflow}
The provable data possession scheme for multiple files operates through five polynomial-time algorithms:
\begin{itemize}
    \item $\Setup(\lambda) \to \mathsf{pp}$: Generates public parameters $\mathsf{pp}$, including bilinear group tuples $(\GG_1, \GG_2, \GG_T, e)$, a structured reference string (SRS) for degree $s-1$, and cryptographic hash functions $H_1$ (for Merkle Tree) and $H_2, H_2$ (for Fiat-Shamir transcript hashing).
    \item $\Store(\{F_i\}_{i=1}^m) \to (\mathsf{data}, \mathsf{meta})$: The DO encodes each chunk into $f_{i,j}(X)$, computes tags $\sigma_{i,j}$, constructs the Merkle Tree to obtain the root hash $\Gamma_i$ for each file, and outsources $\{F_i, \{\sigma_{i,j}\}, \text{Merkle trees}\}$ to the CS. The DO securely records $\{\Gamma_i\}_{i=1}^m$ and shares them with V.
    \item $\Chal(m,n,c) \to \mathsf{chal}$: The verifier samples a shared challenge index set $J \subseteq [n]$ with $|J| = c$, random aggregation coefficients $\{v_{i,j}\}_{i\in[m], j \in J} \leftarrow \FF_p$, and per-file evaluation points $\{r_i\}_{i=1}^m \leftarrow \FF_p$. For brevity, we omit the index \(i\) in \(v_{i,j}\) and simply write \(v_j\) to denote \(v_{i,j}\). The challenge is $\mathsf{chal} = (J, \{v_j\}, \{r_i\}, nonce)$, where $nonce$ is a random value to resist replay attack.
    \item $\ProofGen(\mathsf{chal}, \mathsf{data}, \mathsf{meta}) \to \pi$: The CS aggregates challenged chunks $J$ and outputs the corresponding non-interactive proofs $\pi$.
    \item $\Verify(\mathsf{chal}, \pi, \{\Gamma_i\}, \mathsf{pp}) \to \{accept, reject\}$: V validates the integrity of all files $[m]$ via the proofs $\pi$.
    % The verifier requires only a constant number of pairings (4, or 2 with random batching) independent of $m$.
\end{itemize}

\subsection{Security Model}
\label{sec:security_model}
The security of the proposed batch-PDP scheme is formalized through three core properties: correctness, soundness, and privacy.

\textbf{Correctness}: If all parties (DO, CS, and V) execute the protocol honestly according to the specified algorithms, the $\mathsf{Verify}$ algorithm outputs $accept$ with probability $1$.

\textbf{Soundness}:
Let $\mathcal{A}$ be a probabilistic polynomial-time (PPT) adversary controlling the CS. $\mathcal{A}$ wins the soundness game if it can produce a proof $\pi$ that causes $\Verify$ to output $accept$ for a challenge involving corrupted, modified, or unavailable data chunks with non-negligible probability. 

\textbf{Privacy against Honest-but-Curious Verifier}:
Given the public audit transcript and the generated proof $\pi$, a PPT verifier cannot recover the challenged evaluations $\{y_i = f_i(r_i)\}_{i=1}^m$ or the underlying raw data sectors with non-negligible advantage.

The $\Setup$ algorithm initializes the cryptographic environment and publishes the system-wide public parameters $\mathsf{pp}$. It first generates a bilinear group tuple $(\GG_1, \GG_2, \GG_T, e)$ of prime order $p$, selects public generators $g \in \GG_1$ and $h \in \GG_2$, and samples a secret trapdoor $\tau \in \FF_p$. Cryptographic hash functions are fixed: $H_1$ for Merkle Tree construction, and $H_2$ for Fiat-Shamir transcript binding. Finally, $\mathsf{pp} = (\GG_1, \GG_2, \GG_T, e, p, g, h, \mathsf{SRS}, H_1, H_2)$ is published. \end{algorithmic}
\end{algorithm}


\paragraph{\textbf{Files Storing}}
The $\Store$ algorithm handles data preprocessing, cryptographic tagging, and metadata generation for outsourcing. For each file $F_i$ ($i \in [m]$), the Data Owner parses every chunk $j \in [n]$ into $s$ field elements and algebraically encodes them as a polynomial $f_{i,j}(X) = \sum_{k=0}^{s-1} m_{i,j,k} X^k$. A KZG homomorphic tag $\sigma_{i,j} = g^{f_{i,j}(\tau)} \in \GG_1$ is computed for each chunk, providing a compact cryptographic binding to the underlying data sectors. Note that \(\tau\) is chosen and known by the data owner, so the computation of tag \(\sigma_{i,j}\) can be performed in constant time. 
Then, these tags are organized as leaves in a Merkle Tree with root $\Gamma_i$. The tree roots $\{\Gamma_i\}$ are securely retained by the DO (and later shared with the Verifier), while the raw data and tags are outsourced to the CS. This structure guarantees both data integrity and index authenticity without requiring the DO to maintain local copies.

\end{algorithmic}
\end{algorithm}

\subsection{Security Analysis}
We formally establish the correctness, soundness, and privacy of the proposed batch-PDP scheme. The security analysis relies on the following standard cryptographic assumptions:

\begin{assumption}[Collision-Resistant Hash]\label{ass:hash}
The hash functions $H_1$ (for Merkle tree construction) and $H_2$ (for Fiat--Shamir transcript binding) are collision-resistant. No PPT adversary can find distinct inputs $x \neq x'$ such that $H_1(x) = H_1(x')$ or $H_2(x) = H_2(x')$ with non-negligible probability.
\end{assumption}

\begin{assumption}[KZG Knowledge Soundness]\label{ass:kzg_soundness}
The KZG polynomial commitment scheme over $(\mathbb{G}_1, \mathbb{G}_2, \mathbb{G}_T, e)$ is evaluation-binding and knowledge-sound under the $q$-SDH assumption. Specifically, for any PPT adversary producing a valid opening proof $\pi$ for commitment $C = g^{f(\tau)}$ at point $z$ with value $v$, there exists a PPT extractor that outputs the unique polynomial $f(X) \in \FF_{<s}[X]$ satisfying $f(z) = v$.
\end{assumption}

\begin{assumption}[Discrete Logarithm Hardness]\label{ass:discrete_log}
The discrete logarithm problem in $\mathbb{G}_1$ is computationally intractable. Given $g \in \mathbb{G}_1$ and $Y = g^y$, no PPT adversary can recover $y \in \FF_p$ with non-negligible advantage.
\end{assumption}

\begin{theorem}[Correctness]\label{thm:correctness}
If the Data Owner, Cloud Server, and Verifier execute Algorithms~\ref{alg:store},~\ref{alg:chal},~\ref{alg:proofgen}, and~\ref{alg:verify} honestly, then $\Verify$ outputs $accept$ with probability $1$.

\begin{proof} For each file $i \in [m]$, the server aggregates the challenged chunks into $f_i(X) = \sum_{j \in J} v_j f_{i,j}(X)$ and computes $y_i = f_i(r_i)$. By construction, $f_i(r_i) - y_i = 0$, so $(X - r_i)$ divides $f_i(X) - y_i$ exactly. Thus, the per-file quotient $w_i(X) = \frac{f_i(X) - y_i}{X - r_i}$ is a well-defined polynomial over $\FF_p$ with $\deg(w_i) \leq s-2$. The batch quotient-sum polynomial $W(X) = \sum_{i=1}^m \rho^{i-1} w_i(X)$ consequently satisfies $\deg(W) \leq s-2$, ensuring all associated commitments lie within the SRS degree bound.

\noindent\textit{Step 1: Tag Authentication.} The Merkle authentication paths $\mathsf{Auth}_i$ are constructed honestly from the leaves $\{\sigma_{i,j}\}_{j \in J}$, so they verify against the trusted root $\Gamma_i$ with probability 1 under the collision resistance of $H_1$. 

\noindent\textit{Step 2: Tag Consistency Pre-checks.} 
For tag recombination, the verifier verifies:
\begin{align}
b=&\prod_{i=1}^m g^{f_i(\tau)} =\prod_{i=1}^m g^{\sum_{j\in J} v_{i,j} f_{i,j}(\tau)}\notag\\
=& \prod_{j \in J} \left(g^{f_{i,j}(\tau)}\right)^{v_j} =\prod_{i=1}^m \prod_{j \in J} \sigma_{i,j}^{v_j}=g^{f_i(\tau)}.    \notag
\end{align}

\noindent\textit{Step 3: Cross-File Quotient Folding Commitment and Batch KZG Opening Verification.} 
% The verifier computes the batch commitment $C_W = \prod_{i=1}^m C_{w_i}^{\rho^{i-1}}$, with random value $\rho\gets H_2(\cdots,``1")$. Then, it samples $z \leftarrow H_2(\dots,``2")$ and obtains $z \neq {r_i}$ for $\forall i$. 
KZG batch proof for quotient folding polynomial $W(X)$ is $\pi_{\text{batch}} = g^{\frac{W(\tau) - V_W}{\tau - z}}$, where $V_W = W(z)$. Fresh one-time masks are applied: $\tilde{V}_W = V_W + \eta$ and $R_W = g^{\eta}$. Substituting these into the pairing check yields:
\begin{align}
&e(C_W \cdot g^{-\tilde{V}_W} \cdot R_W \cdot \pi_{\text{batch}}^z, h)     \notag\\
= &e(g^{W(\tau)} \cdot g^{-(V_W + \eta)} \cdot g^{\eta} \cdot g^{z \cdot \frac{W(\tau) - V_W}{\tau - z}}, h) \notag\\
=&e(g^{W(\tau) - V_W - \eta + \eta + z \cdot \frac{W(\tau) - V_W}{\tau - z}}, h )\notag\\
=&e(g^{(W(\tau) - V_W)\!(1 + \frac{z}{\tau - z})},h) \notag\\
= &e(g^{(W(\tau) - V_W) \frac{\tau}{\tau - z}},h).\notag\\
= &e(\pi_{\text{batch}}, h^{\tau})\notag
\end{align}
% By bilinearity, the left-hand side equals $e\!\left(g^{\frac{W(\tau) - V_W}{\tau - z}}, h^{\tau}\right) = e(\pi_{\text{batch}}, h^{\tau})$, which matches the right-hand side. Thus, the pairing equation holds perfectly.

\noindent\textit{Step 4: Cross-File Evaluation Consistency.} The verifier checks the scalar relation:
\begin{align}
    \mathsf{LHS} 
    =& g^{\tilde{V}_W} \cdot R_W^{-1} \cdot g^{-\sum_{i=1}^m \frac{\rho^{i-1}(\tilde{v}_{i,z} - \tilde{y}_i)}{z - r_i}} \notag\\
    =& g^{V_W + \eta} \cdot g^{-\eta} \cdot g^{-\sum_{i=1}^m \frac{\rho^{i-1}\big((v_{i,z} + \nu_i) - (y_i + \mu_i)\big)}{z - r_i}} 
    \notag\\
    =& g^{V_W} \cdot g^{-\sum_{i=1}^m \frac{\rho^{i-1}(v_{i,z} - y_i)}{z - r_i}} \cdot g^{\sum_{i=1}^m \frac{\rho^{i-1}(\mu_i - \nu_i)}{z - r_i}} \notag\\
    =& \left( g^{V_W - \sum_{i=1}^m \frac{\rho^{i-1}(v_{i,z} - y_i)}{z - r_i}} \right) 
    \cdot \left( \prod_{i=1}^m g^{(\mu_i -\nu_i)\frac{\rho^{i-1}}{z - r_i}} \right)  \notag\\
    =& g^{V_W - V_W} \cdot \left( \prod_{i=1}^m (R_i\cdot S_i^{-1})^{\frac{\rho^{i-1}}{z - r_i}} \right)\notag\\
    % =& 1 \cdot \left( \prod_{i=1}^m R_i^{\frac{\rho^{i-1}}{z - r_i}} \right) \cdot \left( \prod_{i=1}^m S_i^{-\frac{\rho^{i-1}}{z - r_i}} \right) \notag\\
    =& \mathsf{RHS} \notag
\end{align}


Since all verification checks (Merkle authentication, tag combination, KZG batch opening, and cross-file consistency) are satisfied with probability 1 under honest execution, the $\Verify$ algorithm outputs $accept$.
\end{proof}

Under Assumptions~\ref{ass:hash}--\ref{ass:discrete_log} and modeling $H_2$ as a random oracle, if $\mathcal{A}$ outputs a proof $\pi$ that causes \textsf{Verify} to accept for a challenge involving corrupted or unavailable data, then $\mathcal{A}$ succeeds with probability at most $\frac{s+m-1}{p-m} + \text{negl}(\lambda)$.
\end{theorem}

\begin{proof}

\textit{Game 0: Real Soundness Game.} Identical to the real protocol execution. By definition, $\Pr[\mathsf{Win}_0] = \epsilon$.

\textit{Game 1: Index Authenticity \& Tag Binding.} The challenger strictly enforces Merkle path verification against the trusted roots $\{\Gamma_i\}_{i=1}^m$ and verifies the tag recombination $\prod_{j\in J} \sigma_{i,j}^{v_j} \stackrel{?}{=} b_i$. The tag binding relies on the homomorphic property of KZG commitments and the discrete logarithm assumption in $\mathbb{G}_1$. Any successful deviation by $\mathcal{A}$ implies breaking $H_1$ or forging a KZG tag, both of which occur with negligible probability. Thus, $|\Pr[\mathsf{Win}_0] - \Pr[\mathsf{Win}_1]| \le \mathsf{negl}(\lambda)$.

\textit{Game 2: Quotient-Consistency Enforcement.} Identical to Game 1, except the challenger strictly enforces the batch KZG opening verification equation from Algorithm~\ref{alg:verify}, Step 2.
% Specifically, after recomputing the folded quotient commitment $C_W = \prod_{i=1}^m C_{w_i}^{\rho^{i-1}}$, the challenger verifies the pairing equality: $

Concretely, the check forces the existence of polynomials $\{w_i(X)\}_{i=1}^m$ such that $W(X) = \sum_{i=1}^m \rho^{i-1} w_i(X)$ and $w_i(\tau) = (f_i(\tau) - y_i)/(\tau - r_i)$ for all $i \in [m]$.

Constructing such a proof implies either forging a valid KZG evaluation binding or solving the discrete logarithm problem in $\GG_1$, both of which occur with negligible probability. Therefore, the transition between games is statistically indistinguishable to any PPT adversary:

\left|\Pr[\text{Win}_1] - \Pr[\text{Win}_2]\right| \le \text{negl}(\lambda).

\]
at the random oracle-derived point $z \in \mathbb{F}_p \setminus \{r_i\}_{i=1}^m$.

$\hat{W}(X) \in \mathbb{F}_p^{\leq s-2}[X]$ such that $C_W = g^{\hat{W}(\tau)}$ and $\hat{W}(z) = V_W$.
The adversary $\mathcal{A}$ wins in Game 2 but loses in Game 3 only if it forges a proof where 
$\hat{W}(z) = h(z)$ for a corrupted file $i^*$ satisfying $f_{i^*}(r_{i^*}) \neq y_{i^*}$, where we define the rational function
\[
h(X) := \sum_{i=1}^m \rho^{i-1} \frac{f_i(X) - y_i}{X - r_i}.
\]
Mapping to the notation of Lemma~\ref{lem:zmdl}, set $u_i(X) \leftarrow f_i(X) - y_i$ and $v_i(X) \leftarrow X - r_i$.

We have $k_1 := \max_i (\deg(u_i) - \deg(v_i)) = s-2$ and $k_2 := \sum_{i=1}^m \deg(v_i) = m$. 
Since $(X - r_{i^*}) \nmid u_{i^*}(X)$, the zero-multiplicity condition $z\text{mult}(v_{i^*}) \sqsubseteq z\text{mult}(u_{i^*})$ is violated.
By the contrapositive of Lemma~\ref{lem:zmdl}, $h(X)$ is algebraically far from any polynomial in $\mathbb{F}_p^{\leq s-2}[X]$. 
Consequently, the probability that a uniformly random $z \in \mathbb{F}_p \setminus Z$ (sampled after commitments are fixed) satisfies $h(z) = \hat{W}(z)$ is bounded by the agreement set size:
\begin{align}
\Pr_{z} \big[ h(z) = \hat{W}(z) \big] \leq \frac{k_1 + k_2 + 1}{p - |Z|} = &\frac{(s-2) + m + 1}{p - m} \notag \\
= &\frac{s + m - 1}{p - m}.\notag 
\end{align}
Therefore, the game transition satisfies $\left| \Pr[\text{Win}_2] - \Pr[\text{Win}_3] \right| \leq \frac{s + m - 1}{p - m}$.

Combining all game transitions yields
\[
\epsilon \le \frac{s+m-1}{p-m} + \mathsf{negl}(\lambda),
\]
which completes the proof.
\end{proof}


\begin{theorem}[Privacy against Honest-but-Curious Verifier]
Under Assumption~\ref{ass:discrete_log} and assuming that the masking scalars $\{\mu_i\}_{i=1}^m$, $\{\nu_i\}_{i=1}^m$, and $\eta$ are freshly and uniformly sampled from $\FF_p$ in each audit round, no PPT honest-but-curious verifier can recover the challenged evaluations $\{y_i = f_i(r_i)\}_{i=1}^m$ or the underlying raw data sectors $\{m_{i,j,k}\}$ from the audit transcript and proof $\pi$ with non-negligible advantage.
\end{theorem}

\begin{proof}
We prove privacy via a standard simulation-based argument. We construct a probabilistic polynomial-time (PPT) simulator $\mathcal{S}$ that, given only the public parameters $\mathsf{pp}$, the Merkle roots $\{\Gamma_i\}_{i=1}^m$, and the challenge $\mathsf{chal}$, generates a simulated proof $\pi_{\mathsf{sim}}$ that is computationally indistinguishable from a real proof $\pi$ generated by an honest cloud server. If such a simulator exists, the verifier's view reveals no information about the underlying data beyond the public challenge.

Let the real transcript be $\mathcal{T} = (\mathsf{chal}, \pi,$ $\{\Gamma_i\}_{i=1}^m)$, where $\pi$ contains the tuple $(\{\mathsf{Auth}_i, b_i, \tilde{y}_i, R_i, C_{w_i},$ $\{\sigma_{i,j}\}_{j \in J}\}_{i=1}^m,$ $\tilde{V}_W, R_W,$ $\pi_{\mathsf{batch}}, \{\tilde{v}_{i,z}, S_i\}_{i=1}^m)$.

The simulator $\mathcal{S}$ proceeds as follows:
\begin{enumerate}
    \item $\mathcal{S}$ copies the public structural elements identically: the challenge $\mathsf{chal}$, the Merkle authentication paths $\{\mathsf{Auth}_i\}_{i=1}^m$, the aggregated tags $\{b_i\}_{i=1}^m$, the per-file and global commitments $\{C_{w_i}\}$, and the individual challenged tags $\{\sigma_{i,j}\}$. These values are either public, deterministically derived from public parameters, or cryptographically bound to file/chunk indices; they do not leak raw sector values without solving the discrete logarithm or breaking the collision resistance of $H_1$.
    \item For each file $i \in [m]$, $\mathcal{S}$ samples $\tilde{y}_i' \leftarrow \FF_p$, $\tilde{v}_{i,z}' \leftarrow \FF_p$, and $\tilde{V}_W' \leftarrow \FF_p$ uniformly at random.
    \item For each $i \in [m]$, $\mathcal{S}$ samples independent random group elements $R_i', S_i' \leftarrow \mathbb{G}_1$ and $R_W' \leftarrow \mathbb{G}_1$.
    \item $\mathcal{S}$ samples a random group element $\pi_{\mathsf{batch}}' \leftarrow \mathbb{G}_1$.
    \item $\mathcal{S}$ assembles $\pi_{\mathsf{sim}}$ using the components above and outputs $(\mathsf{chal}, \pi_{\mathsf{sim}}, \{\Gamma_i\}_{i=1}^m)$.
\end{enumerate}

We now establish the indistinguishability between $\mathcal{T}$ and $\mathcal{T}_{\mathsf{sim}}$ through the following properties:
\begin{itemize}
    \item \textit{Statistical Hiding of Evaluations.} In the real protocol, the masked evaluations are computed as $\tilde{y}_i = y_i + \mu_i$, $\tilde{v}_{i,z} = f_i(z) + \nu_i$, and $\tilde{V}_W = V_W + \eta$, where $\mu_i, \nu_i, \eta \leftarrow \FF_p$ are freshly sampled uniform random scalars. By the one-time pad property, each masked value is statistically uniformly distributed over $\FF_p$ and independent of the underlying true values $y_i$, $f_i(z)$, and $V_W$. Consequently, the simulator's random choices $\tilde{y}_i', \tilde{v}_{i,z}', \tilde{V}_W'$ are identically distributed to the real values, yielding perfect statistical hiding: $I(y_i; \tilde{y}_i) = 0$.
    \item \textit{Computational Hiding of Mask Scalars.} The real masking commitments are $R_i = g^{\mu_i}$, $S_i = g^{\nu_i}$, and $R_W = g^{\eta}$. Under Assumption~\ref{ass:discrete_log}, no PPT adversary can recover the exponents $\mu_i, \nu_i, \eta$ from these group elements with non-negligible probability. Since the simulated commitments $R_i', S_i', R_W'$ are uniformly random elements in $\mathbb{G}_1$, they are computationally indistinguishable from the real commitments under the discrete logarithm assumption.
    \item \textit{Hiding of Polynomial Commitments.} The KZG commitments $\{C_{w_i}\}$, and the opening proof $\pi_{\mathsf{batch}}$ are computed over the public SRS without revealing the trapdoor $\tau$. By the construction of the KZG scheme, these commitments are perfectly hiding with respect to the polynomial coefficients. They only certify algebraic consistency at the queried points (which are already statistically masked). Without knowledge of $\tau$ or the underlying polynomials, these group elements leak zero information about the raw sector coefficients $\{m_{i,j,k}\}$ or the evaluation claims.
\end{itemize}

Combining the above, the joint distribution of the field elements in $\pi$ is statistically independent of the underlying data, while the group elements are computationally indistinguishable from random under Assumption~\ref{ass:discrete_log}. Therefore, the real transcript $\mathcal{T}$ and the simulated transcript $\mathcal{T}_{\mathsf{sim}}$ are computationally indistinguishable for any PPT honest-but-curious verifier. It follows that
\[
\Pr[\mathcal{V} \text{ recovers } \{y_i\} \text{ or } \{m_{i,j,k}\} \mid \mathcal{T}] \leq \mathsf{negl}(\lambda),
\]
which completes the proof.
\end{proof}



\subsection{Complexity Analysis}
\label{sec:complexity_analysis}
We measure computational overhead in terms of group exponentiations in $\GG_1$ ($E$), and bilinear pairings ($P$). Communication overhead is measured in bits using $|p|$, $|G_1|$, and $|h|$ to denote the bit lengths of a field element, a group element, and a cryptographic hash digest, respectively.

\paragraph{Computation Complexity.} 
% Neglecting lightweight Merkle hash operations, overhead is measured in group exponentiations ($E$) and bilinear pairings ($P$).
\begin{itemize}
    \item $\Store$ Algorithm. Since the DO holds the secret trapdoor $\tau$, each homomorphic tag $\sigma_{i,j}=g^{f_{i,j}(\tau)}$ is computed via direct polynomial evaluation in $1E$. Across $m$ files and $n$ chunks, the total cost is $mnE$.
    \item $\ProofGen$ Algorithm. For each file $i \in [m]$, the CS computes the privacy commitment $R_i = g^{\mu_i}$ ($1E$), and commits to the per-file quotient polynomial $C_{w_i}$ ($(s-1)E$). 
    Calculating $b$ requires $sE$. Per-file point evaluations and masking commitments $\{S_i\}_{i=1}^m$ cost $mE$. The global masking commitment $R_W$ costs $1E$, and the KZG opening proof $\pi_{\text{batch}}$ requires committing to a degree-$(s-3)$ quotient polynomial ($(s-2)E$). 
    % Polynomial divisions, scalar masking, and power computations involve $\mathcal{O}(ms + mc)$ field operations. 
    Summing these components, the prover's exact cryptographic workload is $(ms+m+2s-1)E$, which scales as $\mathcal{O}(msE)$.
    \[
\underbrace{msE}_{\text{Step 1}} + \underbrace{(s+m+1)E}_{\text{Step 2}} + \underbrace{(s-2)E}_{\text{Step 3}} = (ms + m + 2s - 1)E,
\]
    \item $\Verify$ Algorithm. The verifier recomputes aggregated tags $b$ ($mcE$) and the folded quotient commitment $C_W$ ($mE$). The batch KZG opening check (i.e., Step 3), requiring $2E+2P$. The cross-file consistency check (i.e., Step~4) requires $3E$ for $\mathsf{LHS}$ and $mE$ for $\mathsf{RHS}$.
    Thus, the verifier performs $(mc + 2m + 3)E+2P$ cryptographic operations.
    % Crucially, the pairing count remains constant ($2P$) and independent of the batch size $m$, file parameters $n, s$, or challenge size $c$.
    \[
\underbrace{mcE}_{\text{Step 2}} + \underbrace{mE}_{\text{Step 3}} + \underbrace{(m+3)E}_{\text{Step 4}} = (mc + 2m + 3)E+2P,
\]
\end{itemize}





\paragraph{Communication Complexity.}


\begin{itemize}
    \item $\Store$ Algorithm. The DO transmits raw file data to the CS, incurring $mns|p|$ bits. Concurrently, $mn$ homomorphic tags $\{\sigma_{i,j}\}$ are outsourced to enable future homomorphic aggregation, costing $mn|\GG_1|$ bits. The DO securely shares $m$ Merkle root hashes $\{\Gamma_i\}_{i=1}^m$ with the verifier for audit authentication, requiring $m|h|$ bits. The total one-time outsourcing communication is $mns|p| + mn|\GG_1| + m|h|$.
    \[
\underbrace{mns|p|}_{\text{File data}} + \underbrace{mn|\GG_1|}_{\text{Tags}} + \underbrace{m|h|}_{\text{Merkle roots}}=mns|p| + mn|\GG_1| + m|h|,
\]
    \item $\ProofGen$ Algorithm. For each file $i \in [m]$, the proof payload includes $(\mathsf{Auth}_i, \tilde{y}_i, R_i, C_{w_i}, \{\sigma_{i,j}\}_{j\in J})$, contributing $c|\GG_1| + 2|\GG_1| + |p| + c\log_2 n |h|$ per file. The cross-file aggregation includes $(b,\tilde{V}_W, R_W, \pi_{\text{batch}}, \{\tilde{v}_{i,z}, S_i\}_{i=1}^m)$, adding $3|\GG_1| + |p| + m(|\GG_1| + |p|)$ bits. Aggregating across all files, the total audit proof size scales as:
    \[
        (mc+3m+3)|G_1| + (2m+1)|p| + mc\log_2 n |h|).
    \]

\end{itemize}






\subsection{Dynamic File Management}
The scheme natively supports file addition and deletion through independent per-file KZG commitments and modular Merkle trees. Crucially, $\ProofGen$ and $\Verify$ are stateless per audit round; they operate on the current active file set without maintaining persistent or incremental proof state. Dynamic operations thus only affect the $\Store$ phase and metadata synchronization.


When the DO uploads a new file $F_{m+1}$, it encodes each chunk into $f_{m+1,j}(X)$, computes tags $\sigma_{m+1,j}=g^{f_{m+1,j}(\tau)}$, and constructs a fresh Merkle tree yielding root $\Gamma_{m+1}$. The data and tags are outsourced to the CS, while $\Gamma_{m+1}$ is securely shared with the verifier. The active batch size increments to $m \leftarrow m+1$. Subsequent audits automatically incorporate $F_{m+1}$ via the expanded index collection and Merkle root set.


To securely remove $F_{i_{\text{del}}}$, the CS permanently erases the associated data, tags, and Merkle nodes. The DO and V discard $\Gamma_{i_{\text{del}}}$. Surviving files simply skip the removed index in subsequent audit loops, incurring zero recomputation of tags or Merkle roots.
The batch size decrements to $m \leftarrow m-1$, and future $\ProofGen$ executions simply iterate over the reduced active set.

\textit{Complexity of Dynamic Operations.} Adding or deleting a single file requires $\mathcal{O}(nE)$ time for tag generation, as implied by the \textsf{Store} algorithm. Importantly, no SRS regeneration, trapdoor rotation, or global commitment recomputation is needed. Since proof generation is challenge-driven and stateless, dynamic updates incur overhead strictly at the storage and metadata layers. Consequently, the \textsf{ProofGen} and \textsf{Verify} algorithms retain the same complexity as analyzed in Section~\ref{sec:complexity_analysis}.

\section{Related Works}
\label{sec:related_works}


Recent years have witnessed significant advances in provable data possession (PDP) schemes for cloud and decentralized storage systems. Several blockchain-assisted auditing mechanisms have been proposed to enhance transparency and eliminate reliance on trusted third-party auditors.

Xu et al. [XuTIFS26] proposed MPA, a lightweight integrity auditing scheme integrating polynomial commitments with Merkle trees for multi-copy decentralized storage. Their design achieves efficient block-level verification and supports dynamic updates through rank-based Merkle tree structures. While MPA enables batch auditing across multiple providers and employs blockchain-based commit-and-reveal protocols for challenge generation, it utilizes a shared evaluation point across all files. 
In the multi-file batch auditing of XuTIFS26, the reliance on a single shared challenge point $r$ introduces a cross-file error cancellation vulnerability. Consider an adversary targeting two audited files $F_i$ and $F_j$. The adversary submits forged evaluation claims $val_i^* = f_i(r) + \delta$ and $val_j^* = f_j(r) - \delta$ for an arbitrary $\delta \in \mathbb{Z}_p^*$. Leveraging the homomorphic property of KZG commitments, the adversary constructs compensating quotient witnesses $w_i^* = g^{h_i(\alpha) - \delta/(\alpha-r)}$ and $w_j^* = g^{h_j(\alpha) + \delta/(\alpha-r)}$, where $h_k(X) = (f_k(X) - val_k^*)/(X-r)$. During verification, the global pairing check evaluates $\hat{e}(\sigma^{\mathsf{global}} \cdot g^{-val^{\mathsf{global}}}, g) \stackrel{?}{=} \hat{e}(w^{\mathsf{global}}, g^{\alpha-r})$. Since the aggregate evaluation error $\sum_k (val_k^* - f_k(r))$ vanishes and the forged witnesses satisfy $\sum_k (\alpha-r) \cdot \log_g w_k^* = \sum_k (f_k(\alpha) - val_k^*)$, the verification equation holds with probability 1. Consequently, the global check accepts the batch despite individual file corruption, demonstrating that the protocol enforces only aggregate polynomial consistency rather than strict per-file soundness.

Zhang et al. [ZhangTPDS23] addressed on-chain storage overhead in decentralized storage networks by employing Boneh et al.'s batch polynomial commitment scheme (PCS-MPAP). Their approach compresses multi-file proofs into constant-sized payloads using a vanishing polynomial $Z_T(X)=\prod_{l=1}^m(X-r_l)$.
% TODO
In batch auditing protocols that publish unmasked linear combinations of plaintext polynomial evaluations on-chain (e.g., $E_i = \sum_{l=1}^{d} \beta_l \cdot S_{l,i}$ and $\{\beta_l\}$ are fixed), a critical privacy vulnerability emerges under the honest-but-curious verifier model. Since the blockchain ledger is fully transparent, an adversary can passively collect audit transcripts across multiple rounds, each utilizing independently sampled folding weights $\{\beta_l^{(t)}\}_{t=1}^{T}$. By aggregating the corresponding on-chain values $\{E_i^{(t)}\}$, the verifier constructs a linear system $\mathbf{E} = \mathbf{B} \mathbf{S}$. When the number of observed rounds $T$ exceeds the batch size $d$, the adversary can efficiently recover the underlying evaluation claims $\{S_{l,i}\}$ via Gaussian elimination, thereby reconstructing sensitive polynomial evaluations and violating the statistical confidentiality of the audited data. This cross-round linear correlation attack underscores the necessity of integrating fresh one-time masking or commitment-based hiding into batch proof generation to prevent plaintext leakage on transparent ledgers.


Yu et al. [YuTC25] designed a lightweight storage verification scheme tailored for resource-constrained Industrial IoT environments. Their innovation eliminates bilinear pairings during verification by transmitting quotient polynomial coefficients directly and leveraging public structured parameters. While this achieves computational efficiency for IIoT devices and supports privacy-enhanced verification through masking techniques, the scheme does not support batch auditing across multiple files. Moreover, explicitly publishing quotient coefficients exposes the underlying polynomial structure, enabling curious verifiers to recover original data sectors through Lagrange interpolation with sufficient challenges, thereby compromising statistical hiding properties.

Miao et al. [MiaoSCIS2026] presented a blockchain-assisted multi-keyword searchable PDP scheme optimized for keyword-filtered auditing in cloud environments. Their protocol employs BLS-type homomorphic signatures with scalar linear aggregation, yielding constant-sized proofs independent of batch size. However, treating each sector as an independent scalar rather than encoding chunks as polynomials forfeits algebraic compression benefits. Consequently, both tag generation and verification scale linearly with total sectors, and privacy protection relies on simple random masking without computational hiding guarantees, offering weaker security against adaptive correlation attacks.

Despite these advances, existing schemes face critical limitations: (1) shared evaluation points enable cross-file error cancellation; (2) lack of explicit tight soundness bounds hinders practical parameter selection; (3) insufficient privacy guarantees expose evaluations to curious verifiers; and (4) heavy on-chain computation or complex polynomial arithmetic limits scalability. Our scheme addresses these gaps through Fiat-Shamir folding over independent per-file quotient polynomials, achieving tight soundness bounds, provable evaluation privacy, and constant-pairing verification without prohibitive computational overhead.

To facilitate a direct comparison, we adopt the unified notation throughout this section: $m$ files in a single audit batch, each comprising $n$ chunks, where each chunk is algebraically encoded as a polynomial of degree $s-1$ (i.e., $s$ sectors per chunk). Let $c$ denote the number of challenged chunks per file.

\noindent\textit{1.1) Computation Complexity of Yu et al.~\cite{YuTC25}}
\begin{itemize}
\item \textbf{\Store{} Algorithm.}  For file \(i\) and chunk \(j\), the data owner evaluates the chunk polynomial at the secret point and computes the homomorphic tag as ours. Therefore, the storage computation is \(mnE\).
\item \textbf{\ProofGen{} Algorithm.} The only counted group exponentiation is the privacy mask \(B=g^\beta\). Therefore, over \(m\) independent files, the computation is \(mE\).
\item \textbf{\Verify{} Algorithm.}  For each file, the verifier reconstructs \(H_Z=g^{Z_{\mathrm{prf}}(\psi)}\) from the \(s\)-coefficient quotient polynomial, derives \(H_{\mathrm{prf}}\), and checks the equation involving \(B^\eta\), \(c\) challenged tags, \(H_Z^{-z}\), and \(\mathrm{HHF}(P_{\mathrm{prf}}(z))\). 
These steps contribute \(2s+c+3\) exponentiations per file. Thus, the verifier computation is \(m(2s+c+3)E\).
\end{itemize}

\item \textbf{\ProofGen{} Algorithm.}  For each file, the response
contains the \(s\)-coefficient quotient polynomial, one evaluation value,

\end{itemize}

\item \textbf{\Store{} Algorithm.}  For each file block, the tag \(\sigma_{i,j}=(H(F_{id}\|i\|j)\cdot g^{f_{i,j}(\alpha)})^x\) requires one exponentiation for \(g^{f_{i,j}(\alpha)}\) and one exponentiation for
the outer secret-key power. Across \(mn\) tags this gives \(2mnE\).

\item \textbf{\ProofGen{} Algorithm.} For each file, exponentiating the \(c\) challenged tags by their audit coefficients costs \(cE\), and applying the file-folding

It also forms \(\psi=g^{-E_1}\cdot W_1^{-Z_T(z)}\) and \(u\cdot v^{-z}\), which contributes \(3E\).  The batch equation \(e(\sigma',g)e(\psi,v)=e(\zeta,v)e(W',u\cdot v^{-z})\) contains four pairings. \begin{itemize}
\item \textbf{\Store{} Algorithm.}  The storage phase sends the file copy, containing \(mns\) field sectors, and \(mn\) tags. The storage communication is \(mns|p|+mn|G_1|\).
\item \textbf{\ProofGen{} Algorithm.}  The published proof is
\((\sigma',W_1,W'_1,E_1)\), namely three group elements and one field element.  Therefore the audit-proof communication is \(3|G_1|+|p|\).
\end{itemize}



\noindent\textit{3.1) Computation Complexity of Miao et al.~\cite{MiaoSCIS2026}}
\begin{itemize}
\item \textbf{\Store{} Algorithm.}  In IndexGen, the data owner computes
one match index \(\Omega_i=(H_{F_i}\cdot H_2(FID_i))^{-x}\) per file, so
the counted work is \(mE\).  In AuthGen, the data owner creates one
authenticator
\(\sigma_{i,j}=(H_{F_i}\cdot H_2(FID_i)\cdot H_3(au_{i,j})\cdot
u^{m_{i,j}})^x\) for each block.  Following the same convention as the
scheme's algorithmic cost model, this contributes one counted group
exponentiation per authenticator after the hash and multiplication
terms are omitted, giving \(mnE\).  Therefore the full storage-side
computation is \((m+mn)E\), with no pairing.  If the keyword-index module
is stripped and only the PDP authentication core is compared, this phase
reduces to \(mnE\).
\item \textbf{\ProofGen{} Algorithm.}  After locating the matched set
\(R\), the server computes
\(T=\prod_{i\in R}\prod_{j\in Q}\sigma_{i,j}^{e_{i,j}}\), which costs
\(\rho cE\), and generates the privacy element \(R_g=g^r\), which costs
one more exponentiation.  Thus the proof-generation computation is
\((\rho c+1)E\).
\item \textbf{\Verify{} Algorithm.}  The verifier exponentiates one
match index \(\Omega_i\) for each matched file and \(c\) hash terms
inside each matched file, and it also computes \(u^{\mu_1}\) and
\(R_g^{h_1(T_w,R_g)}\).  These operations contribute
\((\rho+\rho c+2)E\).  The final verification equation has two pairings,
so the verifier computation is \((\rho(c+1)+2)E+2P\).
\end{itemize}

\noindent\textit{3.2) Communication Complexity of Miao et al.~\cite{MiaoSCIS2026}}
\begin{itemize}
\item \textbf{\Store{} Algorithm.}  The data and authenticators sent to
the cloud contribute \(mn|p|+mn|G_1|\).  The match indexes contain one
group element per file, adding \(m|G_1|\).  Thus the normalized storage
communication is \(mn|p|+(mn+m)|G_1|\), excluding auxiliary searchable
index metadata such as addresses and encrypted index matrices.
\item \textbf{\ProofGen{} Algorithm.}  The audit proof
\((T,\mu_1,R_g)\) consists of two group elements and one field element,
so the proof communication is \(|p|+2|G_1|\).
\end{itemize}


\noindent\textit{4.1) Computation Complexity of Xu et al.~\cite{}}
\begin{itemize}
\item \textbf{\Store{} Algorithm.}  For each file and block, the data
owner forms the block polynomial and computes the tag
\(\sigma_{i,j}=g^{f_{m_{i,j}}(\alpha)}\).  Since polynomial evaluation
uses field operations, tag generation contributes one group
exponentiation for each of the \(mn\) tags.  The storage-side
\textsf{TagVerify} step recomputes each commitment from the \(s\) sector
coefficients as a product of public-key powers, which costs \(sE\) per
block tag.  Hashing the Merkle leaves and roots is omitted under the
current computation metric.  Therefore the storage computation is
\(mn(s+1)E\), with no pairing.
\item \textbf{\ProofGen{} Algorithm.}  For each file, the CSP linearly
combines the \(c\) challenged block polynomials, evaluates the
aggregate polynomial at the challenge point, and divides by \(X-r\).
These are field and polynomial operations.  The only counted operation is
the KZG witness \(w_i=g^{h_i(\alpha)}\).  Since \(h_i(X)\) has degree at
most \(s-2\), computing the witness from the structured public key costs
\((s-1)E\) per local proof.  Across \(m\) local proofs, proof generation
costs \(m(s-1)E\), with no pairing.
\item \textbf{\Verify{} Algorithm.}  The verifier first aggregates the
challenged tags by computing
\(\prod_{j=1}^{c}\sigma_{i,a_j}^{v_j}\) for every file, which costs
\(mcE\).  It then computes \(g^{val^{global}}\) and
\(g^{\alpha-r}\), adding \(2E\).  The accepted batch path checks one
global KZG equation, requiring the two pairings
\(\hat e(\sigma^{global}/g^{val^{global}},g)\) and
\(\hat e(w^{global},g^{\alpha-r})\).  Thus verification costs
\((mc+2)E+2P\).  The fallback diagnosis used only after a failed global
check is not included in this normal verification cost.
\end{itemize}

\noindent\textit{4.2) Communication Complexity of Xu et al.~\cite{}}
\begin{itemize}
\item \textbf{\Store{} Algorithm.}  The storage phase sends \(mn\)
encrypted blocks, each with \(s\) field sectors, and \(mn\) polynomial
tags.  The Merkle root for each file is published as the
verification anchor, and the algorithm also supplies authentication paths
for stored blocks to the corresponding CSP.  Therefore the one-time
storage communication is
\(mns|p|+mn|G_1|+mn\log_2 n|h|+m|h|\).  If the server reconstructs and
stores the Merkle tree locally instead of receiving all paths, the
\(mn\log_2 n|h|\) term can be omitted.
\item \textbf{\ProofGen{} Algorithm.}  For each file, the proof
contains one evaluation value \(val_i\), one witness \(w_i\), the \(c\)
challenged tags, and \(c\) Merkle authentication paths.  Across \(m\)
proofs, the audit-proof communication is
\(m\bigl(|p|+(c+1)|G_1|+c\log_2 n|h|\bigr)\).
\end{itemize}

\section{Evaluation}

\begin{myLem}[Overall Acceptance Probability Bound]
Let $\rho \in [0,1]$ denote the fraction of corrupted or missing chunks in any audited file $F_i$, and let $d = \lfloor \rho n \rfloor$. When the Cloud Server executes $\ProofGen$ over a uniformly sampled challenge set $J \subseteq [n]$ with $|J|=c$, the probability that $\Verify$ outputs $accept$ despite the corruption is bounded by:
\begin{equation}
P_{\text{accept}} \leq \frac{\binom{n-d}{c}}{\binom{n}{c}} + \frac{s}{p} + \text{negl}(\lambda) \approx (1-\rho)^c + \text{negl}(\lambda).
\end{equation}
\end{myLem}

\begin{proof}
Let $E_{\text{miss}}$ be the event that the challenge set $J$ contains no corrupted chunks. Since $J$ is sampled uniformly without replacement from $[n]$, the probability of this event is exactly the hypergeometric ratio:
\[
\Pr[E_{\text{miss}}] = \frac{\binom{n-d}{c}}{\binom{n}{c}}.
\]
When $n \gg c$, this simplifies to $(1-\rho)^c$. In this scenario, the prover can trivially satisfy all verification checks using only intact data.

Let $E_{\text{forge}}$ be the complementary event where $J$ intersects at least one corrupted chunk. For $\Verify$ to still accept, the adversary must successfully forge Merkle authentication paths, satisfy the quotient-consistency pairing, and produce a valid folded KZG opening. By Theorem 2, under the $q$-SDH assumption and random oracle model, the probability of bypassing these cryptographic constraints is bounded by $\frac{s}{p} + \text{negl}(\lambda)$.

Since $E_{\text{miss}}$ and $E_{\text{forge}}$ are mutually exclusive, the total false-acceptance probability satisfies $P_{\text{accept}} = \Pr[E_{\text{miss}}] + \Pr[E_{\text{forge}}]$. Substituting the respective bounds yields the stated inequality. For standard cryptographic parameters ($p \approx 2^{256}$, $s \ll p$), the term $\frac{s}{p}$ is negligible, and the audit security is strictly governed by the sampling parameter $c$.
\end{proof}

\begin{remark}[Parameter Selection]
To achieve a target detection rate $1-\epsilon$ against corruption ratio $\rho$, the challenge size should satisfy $c \geq \frac{\ln \epsilon}{\ln(1-\rho)}$. For example, guaranteeing $99.9\%$ detection for $\rho \geq 1\%$ requires $c \approx 690$. This bound is independent of the batch size $m$ and applies uniformly across all files in the audit.
\end{remark}
